# DevSync Frontend Conventions

This skill governs all frontend work in `frontend/`. Follow it on every React/Tailwind change.

## Stack

- React 19, Vite 8, Tailwind CSS v4 (CSS-first), TypeScript strict.
- UI primitives: **shadcn/ui on Radix** (`src/components/ui/`). Do NOT hand-roll dialogs, dropdowns, menus, tooltips, toasts, switches, tabs, selects, badges, or avatars.
- Icons: `lucide-react`. State: zustand. Drag-and-drop: `dnd-kit`. Editor: Lexical.
- Path alias: `@/*` → `src/*`. Import via `@/...` everywhere, never relative paths.

## Colors — single source of truth

**ALL color values live in `src/theme/colors.ts`.** It is the only file that may contain hex/rgb/hsl literals.

- `frontend/src/theme/colors.ts` — hand-written, typed token map (each token has `dark` + `light` values).
- `frontend/src/theme/tokens.css` — GENERATED by `npm run theme` (`scripts/build-theme.mjs`) from `colors.ts`. Never edit by hand.
- `frontend/src/index.css` — imports `tokens.css`, maps vars into `@theme inline` for Tailwind utilities, defines `@custom-variant dark`.

Rules:
1. **Never write a hex/rgb/hsl literal in a `.ts`/`.tsx` file outside `colors.ts`.** The ESLint rule `no-restricted-syntax` enforces this — if you get flagged, move the value into `colors.ts` (or use a token utility class).
2. **Use semantic token utilities, not raw Tailwind palette colors.** `bg-background`, `text-foreground`, `text-muted-foreground`, `bg-primary`, `text-primary-foreground`, `text-secondary`, `bg-accent`, `border-border`, `ring-ring`, `text-destructive`, `text-success`, `text-warning`, `text-info`, `bg-card`, etc. Never `bg-gray-900`, `text-red-500`, `bg-white`, `text-black`.
3. For JS-inline colors (charts, `style={{}}`), import from `@/theme/colors`:
   - `modeTokens(mode)` → flat `{ background: '#…', foreground: '#…', … }`
   - `resolve(tokenName, mode)` → single value
   - `cssVarName(name)` → the `--token-name` variable
4. Dynamic/DB-provided colors (e.g. user label colors) must go through `assertContrast(hex, mode)` from `@/theme/colors` to guarantee ≥4.5:1 contrast in the active mode.
5. Glassy surfaces use the `glass-*` classes/utilities (`.glass-card`, `.glass-modal`, `.glass-input`, `bg-glass`, `border-glass-border`); they flip automatically per mode. Do not hardcode `rgba(...)` glass.

## Dark / light mode

- Class-based dark mode: `.dark` on `<html>`. Managed by `ThemeProvider` (`src/theme/ThemeProvider.tsx`), persisted to `localStorage['devsync-theme']`, defaulting to `prefers-color-scheme`.
- `index.html` contains an inline FOUC-prevention script that sets `.dark` before first paint.
- Every new color/utility must exist in BOTH token modes. Test both.

## Components

- Use shadcn primitives for all overlays/controls: `Dialog`, `AlertDialog`, `DropdownMenu`, `Tooltip`, `Switch`, `Tabs`, `Select`, `Badge`, `Avatar`, `Command` (command palette / search), `Input`, `Textarea`, `Label`, `Button`, `sonner` (toasts).
- No new conditional-render fixed-overlay modals. If you need a modal, use `Dialog`/`AlertDialog`.
- Icon-only buttons: wrap in `Button variant="ghost" size="icon"` with an `aria-label` describing the action.

## Accessibility — WCAG 2.2 AA (mandatory)

1. **Keyboard**: every control must be reachable and operable by keyboard. Never trigger on `onMouseDown` alone — use `onClick`. Clickable elements are `<button>`/`<a>` or have `role` + `tabIndex` + key handler.
2. **Focus**: never `focus:outline-none` without a visible replacement. Default focus ring = `focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2`.
3. **Names**: all icon-only controls, form inputs, and landmark elements need accessible names (`aria-label`, `<label>`).
4. **Dialogs**: use shadcn `Dialog` (handles focus trap, `aria-modal`, focus restore). Add `aria-label`/`aria-describedby` via `DialogTitle`/`DialogDescription`.
5. **Live regions**: toasts via `sonner` (`role="status"` built in); search/command results get `aria-live="polite"`.
6. **No color-only state**: status, priority, errors, and success always pair an icon or text with the color.
7. **Contrast**: text ≥4.5:1, large text ≥3:1, UI component boundaries ≥3:1 (WCAG 1.4.3 / 1.4.11). Muted text is `text-muted-foreground` (already AA).
8. **Semantics**: use `<nav>`, `<main>`, `<header>`, `<aside>`, `<section>`. Pages have a skip link.

## Verification

- After changes: `npm run lint` and `npm run build` in `frontend/` must pass.
- If the theme changes, re-run `npm run theme` so `tokens.css` stays in sync, then verify in BOTH modes.
- Run the e2e suite (from `e2e/`) when UI structure changes: `npx playwright test`.
